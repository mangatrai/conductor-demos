# v2 — web chat page + front door (design)

Seams used: S1 (client), S2 (registration), S4 (chat contract), S5 (front door, owned here), S6 (manifest).
Everything lives in `convo-agent/v2/`. No new dependencies beyond `fastapi`, `uvicorn`, `requests`;
the page check needs `playwright` (Python) + chromium — platform adds it to `requirements.txt`.

## 1. Layout (one build item per row)

| Path | Item |
|---|---|
| `conductor/workflows/convo_v2_chat_turn.json`, `convo_v2_chat_history.json` | workflows |
| `server.py`, `__init__.py` | server |
| `web/index.html`, `web/app.js`, `web/style.css`, `web/starters.json` | web |
| `gateway/wealth_advisor_service.json`, `gateway/setup_gateway.py`, `gateway/README.md` | gateway |

## 2. Workflows
`convo_v2_chat_turn`: a copy of v1's PRD shape (Switch `has_prev_ref` → optional Get Workflow → JQ `build_ref`
→ `LLM_CHAT_COMPLETE chat_ref` with `{{LLM_PROVIDER}}`/`{{LLM_MODEL}}` input defaults → JQ `save_ref`), output
exactly S4. `convo_v2_chat_history`: input `{executionId, sessionId}`; Switch on empty id → `load_ref`
(Get Workflow, optional) → JQ `answer_ref`:
`(.prev != null and .prev.status=="COMPLETED" and .prev.input.sessionId==.sessionId) as $ok | {found:$ok, history:(if $ok then (.prev.output.history//[]) else [] end), sessionId}`.
Use the same Get-Workflow mechanism v1 uses on OSS (see blocker if OSS lacks the system task).

## 3. Server (`python -m v2.server`)
FastAPI app built by `create_app(version, title, static_dir, client)`; `main()` parses
`--version v2 --port 8720 --title --static-dir --client module:Class` (`--client` default
`common.conductor:Conductor`; the acceptance checks inject a fake Conductor this way — the only test hook).
Workflow names: `convo_{version}_chat_turn` / `_chat_history`. Feature list for `/api/config` comes from
`{version}/manifest.json` `features` (read once; `[]` if absent); title defaults to manifest `title`.

`POST /api/chat` algorithm:
1. Validate: `sessionId` non-empty str ≤100, `message` non-empty str ≤4000 (after strip), `prevExecutionId`
   str (missing→`""`), optional `llmProvider`/`model` str. Else `400 {error}`.
2. Input = those fields; omit `llmProvider`/`model` when absent (workflow defaults apply).
3. `run = client.run_sync(name, input, correlation_id=sessionId, wait_seconds=30)`.
   `ConductorError` → `502 {error}` ("Conductor unreachable" when status 0).
4. `RUNNING`/`PAUSED` → `504 {error, executionId}`; `FAILED|TERMINATED|TIMED_OUT` → `502 {error:
   reasonForIncompletion, executionId}`; `COMPLETED` → 200.
5. 200 body = `run.output` (all keys passed through) + `uiUrl = client.ui_url(workflow_id)`,
   `sessionUrl = client.ui_url(correlation_id=sessionId)`, `elapsedMs`, and **`steps`** (the "what Conductor did"
   panel): `get_workflow(id, include_tasks=True)["tasks"]` mapped to
   `{ref: referenceTaskName, type: taskType, status, ms: endTime-startTime}`; any error here → `steps: []`
   (never fails the turn).

`GET /api/session`: both params required (400); runs chat_history sync; non-COMPLETED or ConductorError → 502.
`GET /api/config`: S5 keys + extras `starters` (from `<static-dir>/starters.json`, else v2's) and `models`
(names from `OLLAMA_URL/api/tags`, 1 s timeout, current model first; on failure `[model]`).
`/healthz` → `{ok:true}`. `/` and static files from `--static-dir` (fallback per file to `v2/web`, so a version
may override only `starters.json` or `style.css`). Logs one line per turn: session, executionId, status, ms.

## 4. Page (`web/`, vanilla JS, no build)
State in `localStorage["convo:" + config.version] = {sessionId, executionId}`.
Stable element ids (the Playwright check depends on them): `#title`, `#messages` (children `.msg.user`,
`.msg.bot`, `.msg.error`), `#input`, `#send`, `#typing`, `#resume-banner`, `#resume-continue`, `#resume-new`,
`#new-chat`, `#exec-link`, `#session-link`, `#starters .starter`, `#model`, `.steps` (a `<details>` under each bot
message listing steps as `ref · type · ms`).
- Load: GET config → title, features chips, starters, model `<select>` (default = config.model). Stored
  executionId → show `#resume-banner` "You left off here. Continue?"; Continue → `/api/session`, redraw history,
  set links; `found:false` → toast "Couldn't restore — starting fresh" + new chat. No → new chat.
- New chat: `crypto.randomUUID()`, empty pointer, clear messages, show starters.
- Send: disable `#send` + `#input`, show `#typing`; POST with stored pointer (+`model` only if the user changed the
  select). 200 → store `executionId`, render reply + steps, update links. Error → `.msg.error` with text and a
  Retry button that resends the same message with the unchanged pointer. Always re-enable after.
- Links are small muted text under the header: "execution ↗" / "session ↗", `target=_blank`, hidden until set.

## 5. Gateway (Orkes)
`wealth_advisor_service.json`: service `wealth-advisor`, API-key auth, CORS origin `http://localhost:8720`,
concurrency limit 5, routes `POST /chat` → `convo_v2_chat_turn` sync 30 s, `GET /session` →
`convo_v2_chat_history` sync. `python -m v2.gateway.setup_gateway [--dry-run]`: flavor `oss` or `--dry-run` →
print the definition and "API Gateway is Orkes-only; the local front door on :8720 stands in", exit 0; `orkes` →
create-or-update via the gateway REST API (endpoint marked **Verify** in README), print the base URL.
The page talks to the gateway when `web/config.local.json` (git-ignored by platform) holds
`{apiBase, apiKey}`; otherwise same-origin `/api`.

## 6. Smoke (`python -m v2.smoke [--base http://localhost:8720]`)
healthz → turn 1 "My client is 55 and wants to retire at 62." → turn 2 "How many years does he have?" with
pointer (reply must contain "7") → `/api/session` found with 4 history items → exit 0, else print why, exit 1.
`manifest.json`: version v2, title "Chat page on a gateway", features ["API Gateway (local stand-in)",
"Sync execution", "Get Workflow resume", "Correlation ID search"], process `web` port 8720 health `/healthz`,
link Chat `http://localhost:8720/`, smoke `["python","-m","v2.smoke"]`.

## 7. Acceptance-check hooks
Offline checks start `python -m v2.server` (cwd `convo-agent/`, `PYTHONPATH=convo-agent:.cc/checks`) with
`--client design_v2_api:FakeConductor`; the fake is defined inside the API check file (the page check imports the
same one), keeps runs in memory, sleeps 0.8 s per run (so the typing state is observable), and is steered per
request by the message text: `"__fail__"` → run FAILED, `"__slow__"` → RUNNING, `"__down__"` → raises
`ConductorError(status=0)`, anything else → COMPLETED echoing a reply and growing history; its chat_history run
answers from its stored runs with the S4 session rule; `get_workflow(include_tasks=True)` returns 3 fake tasks.
It records the last `run_sync` name and input so checks can assert the workflow name, pointer and `model`. Builders must therefore never import `common.conductor`
at module import time in `server.py` except via the `--client` default (lazy `importlib`). The live check needs
`./convo.sh start v2` (Conductor OSS + Ollama) and is the only one that touches real services.
