# v4 — same workflows as MCP tools (design)

Stand-in for the Orkes MCP Gateway on OSS. Snapshot copy of v3's workflows renamed `convo_v4_*`;
an MCP server exposes them as tools. No import from v3 (seam: versions are snapshots).

## Layout (all under `convo-agent/v4/`, owned by this part)
```
conductor/workflows/convo_v4_chat_turn.json      # copy of v3 chat_turn, names -> convo_v4_*, sub wf -> convo_v4_get_portfolio
conductor/workflows/convo_v4_get_portfolio.json  # HTTP task -> {{MOCK_BASE_URL}}/portfolio/${workflow.input.clientName}
conductor/workflows/convo_v4_chat_history.json   # S4 companion
mock_api.py   data/portfolios.json               # own mock, port 8741, GET /portfolio/{name}, /healthz
mcp_server.py                                    # python -m v4.mcp_server [--transport http|stdio] [--port 8740]
claude_desktop/claude_desktop_config.stdio.json  claude_desktop/claude_desktop_config.remote.json  README section
gateway/orkes_mcp_service.json  gateway/SETUP.md # Orkes MCP Gateway service def (flavor orkes)
manifest.json  smoke.py  tests/  README.md
```
Dependency: `mcp` (FastMCP, already in platform list). Claude Desktop remote option uses `npx mcp-remote`
(user's machine, documented only; not needed by tests).

## MCP server
- `FastMCP("convo-v4-wealth-advisor")`; `--transport http` runs Streamable HTTP at
  `http://localhost:8740/mcp` plus `GET /healthz` (custom route) ; `--transport stdio` for Claude Desktop.
  Default transport `http` (that is what the manifest starts).
- Tool `ask_wealth_advisor(message: str, sessionId: str = "", prevExecutionId: str = "",
  llmProvider: str = "", model: str = "")` — schema mirrors S4 input (systemPrompt omitted; workflow default).
  Session pointer algorithm:
  1. key = MCP session id (`ctx.session` identity / `mcp-session-id` header; stdio = one process-wide key).
  2. `sessionId` arg wins; else stored pointer for key; else new `uuid4` → `sessionId`.
  3. `prevExecutionId` arg wins; else stored last good executionId for (key, sessionId); else `""`.
  4. `run_sync("convo_v4_chat_turn", ..., correlation_id=sessionId)`. Only on COMPLETED store
     `executionId` (PRD v1 rule: never advance pointer on failure).
  5. Pointers live in an in-memory dict `{key: {"sessionId", "executionId"}}` — server restart = new chat,
     which is acceptable; callers that pass the args are stateless.
  Empty provider/model args are dropped so workflow defaults apply.
- Tool `get_portfolio(clientName: str)` → `run_sync("convo_v4_get_portfolio", {"clientName"})`.
- Result shape (both tools): `structuredContent` = workflow output + `executionId` + `uiUrl`
  (`Conductor.ui_url(workflow_id)`) + `status`; text content = reply/portfolio summary followed by
  `"Execution: <uiUrl>"` so a human in Claude Desktop sees the link.
- Errors: FAILED/TERMINATED → tool result `isError=true`, text names reason + uiUrl; still RUNNING after
  30 s → `isError=true` with the executionId/uiUrl; ConductorError → `isError=true`, "Conductor unreachable".
  Unknown client → portfolio workflow returns `found:false` (mock 404 handled by v4 workflow switch/JQ), not an error.

## Manifest
processes: `mcp` (`python -m v4.mcp_server --transport http --port 8740`, health `/healthz`) and
`mock` (`python -m v4.mock_api --port 8741`); `mock_base_url_port: 8741`;
links: MCP endpoint `http://localhost:8740/mcp`; smoke `python -m v4.smoke`.

## Smoke (`v4/smoke.py`)
Uses `mcp.client.streamable_http` against 8740: `list_tools` has both; call `get_portfolio("Jane Doe")`
and `ask_wealth_advisor` twice in one session; each result's executionId is fetched with
`Conductor.get_workflow` and must be COMPLETED with `correlationId` = sessionId for the chat turns; the
2nd turn's `restored` is true. Exit 0/1, prints the uiUrls.

## Orkes (flavor orkes)
`gateway/orkes_mcp_service.json`: service `convo-v4-wealth-advisor`, two tools mapping to
`convo_v4_chat_turn` / `convo_v4_get_portfolio` with the same input schemas, auth API key.
`SETUP.md`: create service in UI or via the JSON, copy the "MCP Tool Remote Endpoint", paste into
`claude_desktop_config.remote.json` (`mcp-remote <url> --header X-Authorization:${KEY}`).
On Orkes the mock URL must be public (raw repo URL), documented there.

## Acceptance checks (`.cc/checks/design-v4-*.py`, run from repo root)
Each live check first runs `convo-agent/convo.sh start v4` (idempotent), then talks MCP to
`http://localhost:8740/mcp`. The Conductor-down check launches `python -m v4.mcp_server --transport stdio`
with `CONDUCTOR_SERVER_URL=http://127.0.0.1:9/api` via `mcp.client.stdio` — so `Conductor()` must be built
lazily per call (not at import) and its construction errors mapped to the same "Conductor unreachable" result.
