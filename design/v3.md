# v3 — the chat does real work (portfolio lookup)

Seams used: S1, S2 (`{{MOCK_BASE_URL}}`), S4 (adds `lookup` extra), S5 (reuses `v2.server`), S6.

## 1. Layout (all under `convo-agent/v3/`)

No new Python dependencies (mock uses stdlib).

## 2. Mock portfolio API
`GET /portfolio?name=<str>`: case/space-insensitive match on full name or unique last name.
200 → `{found:true, client:{name, riskProfile, advisor}, totalValue, currency:"USD", asOf,
holdings:[{symbol, name, assetClass, value, weightPct}], ytdReturnPct}`.
Unknown → **200** `{found:false, name, known:[...names]}` (not 404: keeps the HTTP task COMPLETED
so the turn never fails, and lets the bot suggest real names). `GET /clients` → names list.
Jane Doe's numbers are fixed (`totalValue 1250000`, `ytdReturnPct 6.4`) — tests assert them.
`--port` (default 8731), `--fail` flag returns 503 for /portfolio (demo of "API down").

## 3. `convo_v3_get_portfolio` (input `clientName`; output `{found, portfolio, error}`)
1. `http_ref` HTTP task: GET `{{MOCK_BASE_URL}}/portfolio?name=${workflow.input.clientName}`,
   `optional: true`, retryCount 1, timeout 5 s, `connectionTimeOut`/`readTimeOut` 3000.
2. `shape_ref` JQ: `if .resp.statusCode==200 then {found:.resp.body.found, portfolio:.resp.body,
   error:null} else {found:false, portfolio:null, error:"portfolio service unavailable"} end`.
Standalone so v4 can expose it as a tool.

## 4. `convo_v3_chat_turn` (copy v2/v1 turn, then insert before the main LLM call)
- `route_ref` LLM_CHAT_COMPLETE, `jsonOutput:true`, temperature 0, maxTokens 80, messages: system
  = router prompt (few-shot: return only `{"intent":"portfolio"|"chat","clientName":str|null}`),
  user = last 4 history messages flattened + current message (so "and her holdings?" resolves).
- `norm_ref` JQ: robust parse — accepts object or string result; `intent` defaults to `chat`;
  `portfolio` requires non-empty clientName, else `chat`.
- `need_lookup_ref` SWITCH (value-param `${norm_ref.output.result.intent}`): case `portfolio` →
  `lookup_ref` SUB_WORKFLOW `convo_v3_get_portfolio` v1, input `clientName`; default → nothing.
- `ctx_ref` JQ builds `messages` for `chat_ref`: system message = `sys` + (if lookup ran)
  `"\n\nLOOKUP RESULT (use these exact numbers; say if not found/unavailable): " + (tojson)`.
  History part is unchanged → lookup is **never written to history** (`save_ref` uses only
  user msg + reply, as in v1).
- Output adds `lookup`: `null` when no lookup, else `{clientName, found, error,
  subWorkflowId: ${lookup_ref.subWorkflowId}, totalValue}` (summary only, keeps output small).
Graceful cases: unknown → bot says not found and lists `known`; API down → bot says data is
temporarily unavailable; turn status COMPLETED in both.

## 5. Web front door
`v2.server --version v3 --port 8730 --title "Chat that does real work" --static-dir v3/web`.
`web/index.html` = v2 page plus: when response `lookup` is non-null render a card above the reply
"looked up: <clientName>" (+ total value or "not found"/"unavailable") linking to
`conductorUiUrl + "/execution/" + subWorkflowId`. Relies on S5 passing unknown keys through.
