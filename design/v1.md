# v1 — chat_turn with memory across executions

Owner: design-v1. Files: `convo-agent/v1/**`. Seams used: S1 (client), S2 (registration), S4 (chat-turn), S6 (manifest).

## 1. Layout
```
v1/__init__.py
v1/conductor/workflows/convo_v1_chat_turn.json   # the only workflow
v1/chat.py        # terminal client:  python -m v1.chat [--session ID --resume EXEC_ID] [--provider P --model M]
v1/smoke.py       # python -m v1.smoke : 2 real turns, asserts memory, exit 0/1
v1/manifest.json  # processes: [] ; links: Conductor UI search ; smoke: ["python","-m","v1.smoke"]
v1/tests/test_v1_offline.py  # JSON shape + jq logic (no server)
v1/tests/test_v1_live.py     # @pytest.mark.live acceptance tests (PRD v1)
v1/README.md      # presenter walkthrough of the Conductor UI
```
No `conductor/tasks/` (all tasks are system tasks; `convo_llm_chat` belongs to platform).

## 2. Workflow `convo_v1_chat_turn` (version 1)
Exactly the PRD v1 table: `has_prev_ref` SWITCH (javascript evaluator, `$.prev ? 'load' : 'new'`, case `load` →
`load_prev_ref`, default empty) → `build_ref` JSON_JQ_TRANSFORM → `chat_ref` LLM_CHAT_COMPLETE (temperature 0.3,
maxTokens 500) → `save_ref` JSON_JQ_TRANSFORM. jq queries copied verbatim from PRD.
Decisions:
- `load_prev_ref` is `"type": "GET_WORKFLOW"`-style system task with `optional: true`; a missing/foreign id
  makes it FAILED-optional, so `${load_prev_ref.output.workflow}` resolves to null and build_ref starts fresh.
  **OSS fallback** (if the OSS server lacks that task type — builder verifies once with a registration call):
  an `HTTP` task `GET {{CONDUCTOR_API}}/workflow/${workflow.input.prevExecutionId}?includeTasks=false`,
  optional, and build_ref reads `${load_prev_ref.output.response.body}`. Only this one task changes. See blocker.
- `build_ref` also receives `prev` = null when the switch took `new` (unexecuted task output is null).
- `inputParameters` lists all six S4 inputs; defaults via `inputTemplate`:
  `llmProvider: "{{LLM_PROVIDER}}"`, `model: "{{LLM_MODEL}}"`, `systemPrompt: "You are a wealth advisor assistant. Be concise."`.
- `outputParameters` exactly S4: reply, history, executionId (`${workflow.workflowId}`), sessionId, restored.
- Trim = 20 (even), so history always starts with `user`.
- `description` field on the workflow and each task is a one-line plain-English sentence (shows in the UI).

## 3. `v1/chat.py` (terminal client)
- Loop: read line → `Conductor().run_sync("convo_v1_chat_turn", {...}, correlation_id=sessionId, wait_seconds=60)`.
- Only a COMPLETED run advances `prevExecutionId`; FAILED/TERMINATED prints reason + link and keeps the old pointer;
  RUNNING prints "still running" + link.
- After each reply prints `↳ execution: <ui_url(workflow_id)>` and once per session `session: <ui_url(correlation_id)>`;
  `restored=true` on the first turn of a resumed session prints "(memory restored)".
- Pointers saved to `convo-agent/.run/v1_session.json` `{sessionId, executionId}` after every good turn;
  `--resume` (no arg) loads that file; `--session/--resume EXEC_ID` override. Default sessionId `v1-<uuid8>`.
- Slash commands (UX extras): `/new` (fresh session), `/history` (print history from last output), `/links`, `/quit`.
- `--provider/--model` pass `llmProvider`/`model` inputs (provider swap without editing JSON).
- Pure helpers `next_pointer(run, prev)` and `format_turn(run)` kept importable for offline tests.

## 4. `v1/smoke.py`
Fresh sessionId; turn 1 "I am 55 and plan to retire at 62."; turn 2 "How many years until I retire?" chained by
executionId; pass if turn 2 COMPLETED, `restored` true, len(history)==4 and reply contains "7" or "seven". Prints links.

## 5. Tests (`v1/tests/test_v1_live.py`, marked live)
1. memory: the smoke dialog, assert "7"/"seven".
2. trim: 25 turns with short messages (`maxTokens` small via cheap prompt "reply with OK") → final history len 20,
   `history[0].role=="user"`, alternating roles.
3. correlation: 3 turns, `search_by_correlation(sessionId,"convo_v1_chat_turn")` returns all 3 ids.
4. foreign/missing prev: random id and another session's id → COMPLETED, restored false, len(history)==2.
5. provider swap: run with explicit `llmProvider`/`model` input equal to env values and with model override;
   run's `input.model` equals the override and the registered JSON is unchanged (diff file vs `get_workflow_def`).
Offline tests: workflow JSON has the 5 refs in order, optional flag, defaults placeholders, output keys; jq logic
mirrored in Python helper `_expected_history()` only inside tests.
